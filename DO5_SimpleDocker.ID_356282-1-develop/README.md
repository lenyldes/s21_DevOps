Проект представляет собой комплексное практическое исследование и реализацию полного цикла контейнеризации серверных веб-приложений. В рамках работы выполнен переход от базового управления образами и контейнерами через Docker CLI к разработке собственного микросервиса на языке Си с интерфейсом FastCGI, созданию защищенного кастомного Docker-образа в соответствии с рекомендациями CIS Docker Benchmark, аудиту безопасности через утилиту Dockle и развертыванию отказоустойчивой мультиконтейнерной инфраструктуры с двухуровневым обратным проксированием (Reverse Proxy) средствами Docker Compose.

## О проекте

В современной DevOps-инженерии контейнеризация является базовым стандартом изоляции сред выполнения, гарантирующим переносимость, воспроизводимость и детерминированность поведения сервисов на всех этапах жизненного цикла ПО (разработка, тестирование, эксплуатация). Данный проект решает ключевые архитектурные и инфраструктурные задачи:

1. **Изоляция и стандартизация сред (Containerization Paradigm)**:
   Отказ от ручной конфигурации хост-систем в пользу переносимых изолированных контейнеров OCI (Open Container Initiative). Это исключает проблемы конфликта версий системных библиотек, упрощает миграцию сервисов между серверами и обеспечивает унифицированный способ сборки и доставки приложений.

2. **Интеграция Nginx с FastCGI-сервером на языке C**:
   В отличие от устаревшего протокола CGI (Common Gateway Interface), порождающего отдельный процесс операционной системы на каждый поступающий HTTP-запрос, протокол FastCGI сохраняет пул постоянно работающих процессов-демонов. В проекте реализован высокопроизводительный FastCGI-сервер на чистом Си (`server.c`), обрабатывающий входящие TCP-подключения через менеджер процессов `spawn-fcgi` и взаимодействующий с веб-сервером Nginx по протоколу FastCGI через локальный сокет.

3. **Соответствие стандартам безопасности (Container Hardening & CIS Docker Benchmark)**:
   Стандартные контейнеры часто запускаются с правами суперпользователя `root`, что создает критический вектор компрометации хоста в случае побега из контейнера (container breakout). В проекте реализован защищенный Dockerfile: все рабочие процессы Nginx и скомпилированного FastCGI-сервера функционируют под непривилегированным пользователем `nginx`, каталоги кэша и PID-файлов перенастроены по правам доступа, а кэш пакетного менеджера очищается на этапе сборки.

4. **Мультиконтейнерная оркестрация и декомпозиция (Microservices via Docker Compose)**:
   Разделение ответственности между фронтенд-прокси и внутренним сервисом приложений. Публичный периметр принимает запросы на стандартном HTTP-порту 80 и проксирует их во внутреннюю изолированную сеть Docker Bridge, где функционирует защищенный FastCGI-сервер, закрытый от прямого доступа из глобальной сети.

## Ключевые навыки и освоенные концепции

- **Управление жизненным циклом контейнеров через Docker CLI**:
  - Загрузка, инспекция и тегирование официальных образов (`docker pull`, `docker images`, `docker tag`).
  - Фоновый запуск контейнеров в detached-режиме (`docker run -d`), остановка с корректной отправкой сигнала `SIGTERM` (`docker stop`), перезапуск (`docker restart`) и удаление контейнеров (`docker rm`).
  - Глубокий аудит состояния контейнеров через `docker inspect`: фильтрация IP-адресов, структуры привязки портов (`NetworkSettings.Ports`) и анализ размера корневой файловой системы контейнера (`SizeRootFs`) с флагом `-s`.
  - Выполнение команд внутри работающего контейнера без его остановки через `docker exec` (интерактивные сессии bash и передача команд на лету).
  - Снапшотинг и миграция данных: экспорт файловой системы контейнера в плоский архив (`docker export`) и воссоздание базового образа через `docker import` с ручным определением директив запуска.

- **Сетевой маппинг и монтирование томов (Volume & Port Mapping)**:
  - Проброс сетевых портов с хоста в изолированное пространство сетевого стека контейнера (`-p <host_port>:<container_port>`).
  - Применение механизма bind-mount (`-v $(pwd)/...:/etc/nginx/...`) для горячего проброса конфигурационных файлов без пересборки Docker-образа.
  - Бесшовная перезагрузка конфигурации веб-сервера без обрыва клиентских соединений с помощью `nginx -s reload` (graceful reload).

- **Спецификация FastCGI и программирование на C**:
  - Работа с библиотекой FastCGI (`libfcgi-dev`) и системным заголовочным файлом `<fcgiapp.h>`.
  - Инициализация структуры запроса (`FCGX_InitRequest`) и организация неблокирующего цикла обработки событий (`FCGX_Accept_r`).
  - Формирование валидных HTTP-заголовков (`Content-Type: text/html\n\n`) и тела ответа через выводной поток `req.out` функции `FCGX_FPrintF`.
  - Управление сокетами и форками приложения через утилиту `spawn-fcgi` с привязкой к локальному TCP-порту `8080`.

- **Написание оптимизированных и защищенных Dockerfile**:
  - Минимизация слоев файловой системы OverlayFS за счет объединения связанных системных вызовов в единую инструкцию `RUN` через оператор `&&`.
  - Сборка бинарного файла Си внутри сборочного слоя без необходимости сторонних внешних скриптов.
  - Устранение разрастания размера образов путем обязательной очистки кэша пакетного менеджера `rm -rf /var/lib/apt/lists/*` в том же слое, где производилась установка зависимостей.
  - Конфигурирование PID 1 процесса и предотвращение фонового перехода Nginx через запуск на переднем плане (`daemon off;`).

- **Аудит безопасности контейнеров с линтером Dockle**:
  - Изучение и применение требований отраслевого стандарта CIS Docker Benchmark.
  - Устранение уязвимости **CIS-DI-0005** (запуск от имени root): создание условий для перехода на непривилегированного системного пользователя `USER nginx`, включая рекурсивную смену владельца директорий `/var/cache/nginx` и `/run`.
  - Устранение замечания **DKL-DI-0006**: валидация отсутствия временных индексов репозиториев apt.
  - Контроль прав доступа на исполняемые файлы (`chmod +x /app/start.sh`).

- **Оркестрация мультиконтейнерных приложений через Docker Compose**:
  - Декларативное описание распределенной инфраструктуры в файле `docker-compose.yml`.
  - Создание изолированной пользовательской сети типа `bridge` (`part_6`) со встроенным механизмом DNS-резолвинга (Service Discovery по доменным именам сервисов).
  - Настройка порядка инициализации зависимостей с помощью директивы `depends_on`.
  - Разделение внешнего Reverse Proxy и бэкенд-сервера для обеспечения сетевой изоляции.
