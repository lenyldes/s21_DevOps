Проект представляет собой комплекс инженерных скриптов и конфигураций на платформе GNU/Linux, ориентированный на моделирование критических сценариев эксплуатации дисковых подсистем, анализ телеметрии веб-серверов и построение промышленного контура наблюдаемости (observability). В репозитории реализованы алгоритмы детерминированной и вероятностной генерации файловых структур с жестким контролем доступного пространства (порог аварийной остановки 1 Гб), три независимые стратегии восстановления и очистки файловой системы, генератор синтетических журналов Nginx в формате Combined Log Format с потоковыми фильтрами на базе AWK, модуль генерации HTML-отчетов через контейнеризированный GoAccess, а также инфраструктурный стек сбора и визуализации метрик хоста на базе Prometheus, Node Exporter и Grafana в среде Docker Compose.

## О проекте

При эксплуатации высоконагруженных распределенных сервисов и облачной инфраструктуры ключевыми задачами SRE-инженера являются прогнозирование деградации подсистем хранения, быстрая локализация аномалий по журналам доступа и непрерывный мониторинг базовых аппаратных метрик. Проект решает указанные задачи через практическую реализацию следующих функциональных блоков:

1. **Моделирование высокой нагрузки на файловую систему (Storage Stress Testing):**
   - Контролируемое создание глубоких и разветвленных структур каталогов и файлов с заданными параметрами длин имен и объемов.
   - Имитация бесконтрольного разрастания данных на диске с вероятностным алгоритмом случайного обхода дерева каталогов хоста.
   - Выделение дискового пространства через прямой системный механизм быстрой аллокации блоков (`fallocate`) с отказоустойчивым переключением на усечение разреженных файлов (`truncate`).

2. **Предотвращение критического отказа подсистемы хранения (Disk Full Prevention):**
   - Непрерывный мониторинг доступного дискового пространства на корневом разделе (`/`) перед созданием каждого нового объекта.
   - Вычисление свободной емкости с точностью до килобайта через утилиту `df` для предотвращения ошибок округления.
   - Безопасное аварийное завершение работы генераторов при достижении порогового значения остатка в 1 Гб (1 048 576 Кб), исключающее отказ ядра, блокировку системных демонов и сбои журнала файловой системы.

3. **Многофакторная очистка и восстановление файловой системы (FS Sanitization):**
   - Устранение последствий стресс-тестирования без риска повреждения системных файлов и пользовательских данных.
   - Поддержка трех взаимодополняющих стратегий удаления артефактов: десериализация транзакционного журнала генерации, фильтрация по временному диапазону создания (`find -newermt`) и поиск по регулярным маскам имен и дат.
   - Встроенные правила защиты критических системных каталогов (`/bin`, `/sbin`, `/proc`, `/sys`, `/dev`, `/run`, `/boot`).

4. **Синтез и потоковый анализ журналов веб-сервера (Web Telemetry Processing):**
   - Генерация синтетических access-логов веб-сервера за 5 последовательных суток с соблюдением стандарта Nginx Combined Log Format.
   - Эмуляция распределения кодов ответов HTTP (2xx, 4xx, 5xx), разнообразных методов (GET, POST, PUT, PATCH, DELETE), реальных URL-маршрутов и 8 классов User-Agent.
   - Потоковая фильтрация, сортировка и агрегация данных журнала с использованием языка обработки текста `awk` без применения тяжелых внешних сред исполнения.
   - Развертывание легковесного интерактивного веб-дашборда через утилиту `GoAccess`, запущенную в изолированном Docker-контейнере.

5. **Комплексный мониторинг инфраструктуры в реальном времени (Host Observability):**
   - Развертывание оркестрируемого стека Node Exporter + Prometheus + Grafana в едином сетевом пространстве хоста (`network_mode: host`).
   - Сбор метрик с интервалом дискретизации 3 секунды для детальной фиксации кратковременных всплесков утилизации ресурсов.
   - Верификация поведения графиков утилизации CPU, распределения оперативной памяти, операций ввода-вывода (I/O) диска и сетевой пропускной способности под синтетической нагрузкой (`stress`, `clogger`, `iperf3`).

## Ключевые навыки и освоенные концепции

- **Комбинаторные алгоритмы генерации строк на Bash:** Разработка алгоритмов дополнения и модификации строк символов с сохранением исходного алфавитного порядка, динамическим наращиванием длины до нормативных требований (не менее 4 символов для Part 1 и не менее 5 символов для Part 2) и суффиксацией датой запуска в формате `_DDMMYY`.
- **Низкоуровневая работа с дисковым пространством:** Применение утилиты `fallocate` для предварительного выделения неразреженных блоков в файловых системах Linux без забивания диска нулями через `dd`, а также резервный фолбэк на `truncate`.
- **Потоковый разбор системных счетчиков:** Интеграция командного конвейера `df -k / | awk 'NR==2 {print $4}'` для детерминированного контроля остаточной емкости раздела в реальном времени.
- **Стратегии выборочного удаления в Linux:** Применение утилит `find`, `rm`, механизмов захвата групп регулярных выражений Bash (`BASH_REMATCH`) и временных модификаторов утилиты `find` (`-newermt`, `! -newermt`).
- **Спецификация Nginx Combined Log Format:** Генерация записей формата `$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"` со строго монотонно возрастающим таймстемпом в пределах каждых суток.
- **Текстовая аналитика на базе AWK:** Построение однострочных фильтров для извлечения полей логов, фильтрации регулярными выражениями кодов ошибок клиентской и серверной сторон (`$9 ~ /^[45][0-9]{2}$/`), объединения с утилитой `sort` для ранжирования (`sort -k 9 -n`) и дедупликации (`sort -u`).
- **Контейнеризация и интеграция CLI-утилит:** Конвейерная передача потоков данных `cat ... | docker run --rm -i ...` для генерации статических отчетов GoAccess без необходимости установки утилиты на хост.
- **Инфраструктура как код (IaC) с Docker Compose:** Декларативное описание сервисов телеметрии, настройка политик перезапуска (`unless-stopped`), механизмов проверки доступности (`healthcheck`) с зависимостями `condition: service_healthy`, а также маппинга системных директорий хоста (`/:/host:ro,rslave`).
- **Prometheus Time Series Database (TSDB):** Конфигурирование scrape-интервалов сбора данных, таргетов и экспортеров системных метрик.
- **Анализ телеметрии в Grafana:** Импорт и настройка дашбордов для детального отслеживания аппаратных ресурсов под воздействием утилит генерации стресс-нагрузки (`stress`) и пропускной способности сети (`iperf3`).
