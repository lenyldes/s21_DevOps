### 1.2. localhost

- `localhost` (так называемый, «местный» от англ. local, или «локальный хост», по смыслу — этот компьютер) — в компьютерных сетях, стандартное, официально зарезервированное доменное имя для частных IP-адресов (в диапазоне `127.0.0.1 — 127.255.255.254`, RFC 2606). Для сети, состоящей только из одного компьютера, как правило, используется всего один адрес — 127.0.0.1, который устанавливается на специальный сетевой интерфейс «внутренней петли» (англ. loopback) в сетевом протоколе TCP/IP. В Unix-подобных системах данный интерфейс обычно именуется «loN», где N — число, либо просто «lo». 
- `127.0.0.1` и все адреса в диапазоне `127.0.0.0/8` (то есть от `127.0.0.0` до `127.255.255.255`) являются адресами локальной петли (loopback). Это значит, что любые адреса в этом диапазоне могут обращаться к localhost.
- Таким образом к сети (приложению) работающему на `127.0.0.1` (localhost) можно обратиться с адресов: `127.0.0.2`, `127.1.0.1` и нельзя обратиться с адресов: `194.34.23.100`, `128.0.0.1`

### 1.3. Диапазоны и сегменты сетей
- Следующие диапазоны определены IANA как адреса, выделенные локальным сетям: \
`10.0.0.0 — 10.255.255.255` (маска подсети для бесклассовой (CIDR) адресации: 255.0.0.0 или /8); \
`100.64.0.0 — 100.127.255.255` (маска подсети 255.192.0.0 или /10). Данная подсеть рекомендована согласно RFC 6598 для использования в качестве адресов для CGN (Carrier-Grade NAT); \
`172.16.0.0 — 172.31.255.255` (маска подсети: 255.240.0.0 или /12); \
`192.168.0.0 — 192.168.255.255` (маска подсети: 255.255.0.0 или /16); \
`127.0.0.0 — 127.255.255.255` (маска подсети: 255.0.0.0 или /8). Для петлевых интерфейсов (не используется для обмена между узлами сети). \
Таким образом получаем: \
*10.0.0.45* - `частный`, \
*134.43.0.2* - `публичный`, \
*192.168.4.2* - `частный`, \
*172.20.250.4* - `частный`, \
*172.0.2.1* - `публичный`, \
*192.172.0.1* - `публичный`, \
*172.68.0.2* - `публичный`, \
*172.16.255.255* - `частный`, \
*10.10.10.10* - `частный`, \
*192.169.168.1* - `публичный`.

- Для определения какие из перечисленных IP-адресов шлюза возможны у сети `10.10.0.0/18`: *10.0.0.1*, *10.10.0.2*, *10.10.10.10*, *10.10.100.1*, *10.10.1.255* сначала нужно сначала понять, какие адреса входят в эту подсеть. \
Network:   `10.10.0.0/18` \
HostMin:   `10.10.0.1` \
HostMax:   `10.10.63.254` \
Broadcast: `10.10.63.255` \
Таким образом в качестве шлюза могут выступать адреса: `10.10.0.2, 10.10.10.10, 10.10.1.255`. \
При этом последний является широковещательным адресом для своей подсети.

### 5.5. Построение списка маршрутизаторов

- Получим список маршрутизаторов на пути от ws11 до ws21.\
Для этого запустим на r1 команду дампа: `tcpdump -tnv -i enp0s3`, а на машине ws11 команду `traceroute` до сети ws21.

> Вызов команд `tcpdump` и `traceroute` \
![Вызов команд `tcpdump` и `traceroute`](screenshot/5_5_1.png)

- Команда `traceroute` используется для определения маршрута, по которому пакеты проходят от одного узла к другому в сети. Она работает, отправляя пакеты с постепенно увеличивающимся значением поля *Time to Live (TTL)*, что позволяет отслеживать каждый промежуточный узел (хоп) на пути к конечному адресу. \
`traceroute` отправляет пакеты (обычно UDP или ICMP) к целевому адресу, начиная с TTL, равного 1. Это означает, что пакет может пройти только один хоп (один маршрутизатор) перед тем, как будет отброшен.\
Когда пакет достигает маршрутизатора, у которого TTL равен 1, маршрутизатор уменьшает TTL на 1 (в данном случае до 0) и отправляет обратно ICMP-сообщение к исходному узлу (в данном случае к ws11).
`traceroute` получает это ICMP-сообщение и записывает IP-адрес маршрутизатора, который его отправил. Затем он увеличивает TTL на 1 и повторяет процесс, отправляя новый пакет.\
Этот процесс продолжается, пока не будет достигнут конечный узел (ws21).\
Когда мы запускаем `tcpdump -tnv -i enp0s3` на r1, мы начинаем захватывать и отображать сетевой трафик, проходящий через интерфейс `enp0s3`. Мы можем увидеть пакеты, которые приходят и уходят через этот интерфейс, включая ICMP-сообщения и UDP-пакеты, отправляемые ws11 в процессе выполнения `traceroute`.

### 5.6. Использование протокола **ICMP** при маршрутизации

- Запустим на r1 перехват сетевого трафика, проходящего через enp0s3 с помощью команды:

- После чего пропингуем с ws11 несуществующий IP (например, *10.30.0.111*) с помощью команды:

## Part 6. Динамическая настройка IP с помощью **DHCP**

- Потренируемся пользоваться динамической настройкой IP с помощью **DHCP**.
- Для этого сначала настроим роутер r2 на выдачу ip адресов.
- В качестве примера зададим следующие настройки сети в файле */etc/dhcp/dhcpd.conf* конфигурацию службы **DHCP**:
```shell
subnet 10.100.0.0 netmask 255.255.0.0 {}

subnet 10.20.0.0 netmask 255.255.255.192
{
    range 10.20.0.2 10.20.0.50;
    option routers 10.20.0.1;
    option domain-name-servers 10.20.0.1;
}
```
- И в файле */etc/resolv.conf* пропишем следующий публичный DNS сервер (Google) для разрешения доменных имен в IP-адреса:
`nameserver 8.8.8.8`
