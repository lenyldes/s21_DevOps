Модульный инструментарий системного администрирования и DevOps на командном интерпретаторе Bash, предназначенный для сбора низкоуровневой телеметрии операционной системы в реальном времени, форматированного вывода системных метрик с динамической ANSI-стилизацией, гибкого конфигурационного управления и глубокого аудита структуры файловой системы с потоковым вычислением криптографических хешей.

---

## О проекте

В корпоративных средах, закрытых контурах безопасности (air-gapped networks), минималистичных контейнерах и встраиваемых Linux-системах развертывание тяжеловесных агентов телеметрии (Prometheus Node Exporter, Datadog Agent, Zabbix Agent) часто невозможно или нецелесообразно из-за жестких ограничений по оперативной памяти, зависимостей от сторонних сред выполнения (Go, Python, JVM) и дополнительных сетевых векторов атаки.

Данный проект решает задачу безагентного и автономного мониторинга вычислительных узлов под управлением Linux. Комплекс скриптов спроектирован в соответствии с принципами Unix-философии: каждый модуль выполняет строго одну задачу, данные передаются через стандартные потоки ввода-вывода (POSIX pipelines), а в качестве источников информации используются интерфейсы ядра Linux и стандартные утилиты POSIX/GNU.

Основные функциональные направления:
- Мониторинг системных ресурсов в реальном времени: извлечение информации об активных сетевых интерфейсах, шлюзах по умолчанию, масках подсетей (с переводом CIDR в dotted-decimal нотацию с использованием побитовых сдвигов), объеме оперативной памяти (Total, Used, Free), доступности дискового пространства в корневой файловой системе (`/`), времени непрерывной работы системы (в человекочитаемом формате и секундах), таймзонах и версиях ОС.
- Строгая валидация входных данных: превентивный синтаксический и семантический контроль всех CLI-аргументов через регулярные выражения Bash (POSIX ERE). Обработка граничных условий, предотвращение передачи некорректных типов данных и защита от визуальных коллизий (совпадения цветов текста и фона).
- Управление стилизацией и конфигурацией: независимое цветовое оформление информационных колонок посредством 16-цветовых ANSI escape-последовательностей как через аргументы командной строки, так и через внешний конфигурационный файл с автоматическим откатом (fallback) к значениям по умолчанию.
- Профилирование и аудит файловой системы: углубленный рекурсивный анализ заданного каталога, классификация объектов по типам (конфигурации, текстовые файлы, исполняемые бинарники, журналы, архивы, симлинки), ранжирование директорий и файлов максимального объема, расчет контрольных сумм MD5 для крупнейших исполняемых файлов и прецизионный замер времени выполнения сценария с точностью до десятых долей секунды.

## Ключевые навыки и освоенные концепции

- Разработка отказоустойчивых Bash-скриптов:
  - Использование детерминированной смены рабочего каталога через `cd "$(dirname "$0")" || exit 1` для обеспечения корректности относительных путей при запуске из любых точек файловой системы.
  - Управление жизненным циклом процессов, возврат стандартных кодов завершения (`exit 0`, `exit 1`), подавление и перенаправление потоков ошибок (`2>/dev/null`, `2>&1`).
- Модульная компонентная архитектура:
  - Полная декомпозиция монолитного кода на независимые атомарные скрипты с четким разграничением ответственности (Single Responsibility Principle).
  - Бесшовное подключение библиотек и модулей через команду `source` (`.`), переиспользование общих функций и изолированное выполнение дочерних утилит с захватом вывода через command substitution `$()`.
- Валидация CLI-аргументов и регулярные выражения:
  - Проверка количества позиционных параметров (`$#`).
  - Проверка типов входных данных через оператор `[[ $var =~ regex ]]`: фильтрация числовых значений (целых, вещественных с плавающей точкой, отрицательных: `^-?[0-9]+(\.[0-9]+)?$`), проверка диапазонов идентификаторов (`^[1-6]$`).
  - Проверка свойств файловой системы: контроль закрывающего слэша в пути (`${dir: -1}`), проверка существования директорий (`[ -d "$path" ]`), валидация непустого содержимого (`find -mindepth 1`), детекция ограничений прав доступа (`Permission denied`).
- Терминальная графика и ANSI Escape-последовательности:
  - Использование кодов форматирования текста (foreground `\033[3Xm`) и фона (background `\033[4Xm`), сброс стилей через `\033[0m`.
  - Алгоритмический анализ контрастности: валидация пользовательской палитры для исключения нечитаемого текста при совпадении цветов фона и шрифта в столбцах.
- Низкоуровневый сбор метрик и системные интерфейсы ядра:
  - Парсинг виртуальной файловой системы `procfs` (`/proc/uptime`) и конфигураций операционной системы (`/etc/os-release`).
  - Извлечение сетевых параметров через интерфейсы `iproute2` (`ip route show default`, `ip -o -f inet addr show`).
  - Реализация побитовой бинарной арифметики в Bash: вычисление маски подсети по префиксу CIDR через сдвиги `val=$(( 0xFFFFFFFF << (32 - cidr) ))` и побайтовую маску `(( (val >> 24) & 255 ))`.
  - Потоковая обработка и математические расчеты в `awk`: преобразование единиц измерения памяти и диска из байт и килобайт в гигабайты и мегабайты с форматированием точности (`%.3f GB`, `%.2f MB`).
- Конвейерный аудит файловых систем и криптографический анализ:
  - Построение эффективных конвейеров фильтрации и сортировки больших объемов данных: `find`, `du -h`, `sort -hr`, `tail`, `head`.
  - Интеграция межпроцессного взаимодействия (IPC) в `awk`: динамический вызов утилиты `md5sum` через программный канал `cmd = "md5sum " $2; cmd | getline hash; close(cmd)` для вычисления хеш-сумм без создания временных файлов.
- Высокоточный бенчмаркинг и замер производительности:
  - Фиксация наносекундных временных меток с помощью `date +%s.%N`.
  - Вычисление дельты времени выполнения скрипта с помощью встроенного интерпретатора `awk`.

## Архитектура и стек технологий

Проект разделен на 5 автономных модулей (папки `01`–`05`), каждый из которых решает отдельную задачу системного администрирования и развивает архитектурные подходы от базовой валидации до комплексного аудита.

```text
+-----------------------------------------------------------------------------------+
|                           Конвейер обработки данных                               |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [ Входные данные ]        CLI-аргументы ($1..$4) / Файл конфигурации config.cfg   |
|         |                                                                         |
|         v                                                                         |
|  [ Валидация ]             Проверка ARGC, regex-анализ типов, контроль коллизий   |
|         |                                                                         |
|         v                                                                         |
|  [ Сбор метрик / Аудит ]   procfs, sysfs, Coreutils (free, df, ip, find, du, md5) |
|         |                                                                         |
|         v                                                                         |
|  [ Трансформация ]         Арифметический расчет (AWK/Bash), ANSI-стилизация      |
|         |                                                                         |
|         v                                                                         |
|  [ Финальный вывод ]       Форматированный stdout / Экспорт в *.status лог-файл   |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

### Схема взаимодействия компонентов мониторинга (Модули 02, 03, 04)

Главный управляющий скрипт `main.sh` оркестрирует процесс валидации, загрузки конфигурации и формирования отчета:

```text
                                +-------------------+
                                |      main.sh      |
                                +---------+---------+
                                          |
              +---------------------------+---------------------------+
              |                           |                           |
              v source                    v source                    v source
      +---------------+           +---------------+           +---------------+
      |  validate.sh  |           |   config.sh   |           | print_info.sh |
      +---------------+           +-------+-------+           +-------+-------+
                                          |                           |
                                          v source                    |
                                  +---------------+                   |
                                  |   config.cfg  |                   |
                                  +---------------+                   |
                                          |                           |
                                          v source                    |
                                  +---------------+                   |
                                  |   colors.sh   |<------------------+
                                  +---------------+
                                          ^
                                          | вызывает
                                          v
      +-------------------------------------------------------------------------------+
      |                          Метрические модули (*.sh)                            |
      |-------------------------------------------------------------------------------|
      | HOSTNAME.sh   TIMEZONE.sh   USER.sh       OS.sh         DATE.sh               |
      | UPTIME.sh     UPTIME_SEC.sh IP.sh         MASK.sh       GATEWAY.sh            |
      | RAM_TOTAL.sh  RAM_USED.sh   RAM_FREE.sh   SPACE_ROOT.sh SPACE_ROOT_USED.sh    |
      | SPACE_ROOT_FREE.sh                                                            |
      +-------------------------------------------------------------------------------+
```

### Схема конвейера аудита файловой системы (Модуль 05)

Модуль 05 выполняет последовательный анализ заданного дерева каталогов:

```text
                                +-------------------+
                                |   src/05/main.sh  |
                                +---------+---------+
                                          |
                        +-----------------+-----------------+
                        | source                            | source
                        v                                   v
             +--------------------+              +--------------------+
             |  src/05/validate.sh|              |  src/05/analyze.sh |
             +--------------------+              +---------+----------+
             | - Проверка ARGC    |                        |
             | - Проверка '/'     |                        |-- 1. Старт таймера (date +%s.%N)
             | - Проверка пути -d |                        |-- 2. Подсчет каталогов (find -type d)
             | - Проверка прав    |                        |-- 3. ТОП-5 каталогов (du | sort | awk)
             | - Проверка непусто |                        |-- 4. Классификация файлов (conf, txt, log...)
             +--------------------+                        |-- 5. ТОП-10 файлов (find | du | awk)
                                                           |-- 6. ТОП-10 бинарников + MD5 (find | awk md5sum)
                                                           +-- 7. Стоп таймера и вывод времени (awk)
```

### Стек технологий и утилит

| Компонент / Утилита | Область применения в проекте | Решаемая задача |
| :--- | :--- | :--- |
| **GNU Bash (5.0+)** | Базовый интерпретатор | Построение логики, проверка условий, регулярные выражения, побитовая математика |
| **GNU Coreutils** | Системный инструментарий | `date`, `df`, `du`, `head`, `tail`, `sort`, `wc`, `cut`, `whoami`, `hostname`, `md5sum` |
| **GNU Awk (gawk)** | Потоковый процессор | Вычисление отношений величин памяти и диска, форматирование чисел с плавающей точкой, IPC-вызовы |
| **Iproute2** | Сетевая подсистема | Утилита `ip` (`ip route`, `ip addr`) для обнаружения маршрута по умолчанию и сетевых масок |
| **Systemd** | Управление временем ОС | `timedatectl show` для получения часового пояса хоста |
| **Procfs / Sysfs** | Виртуальная ФС ядра | Файл `/proc/uptime` для прямого считывания точного времени работы ядра |
| **ANSI Escape Codes** | Графический вывод в TTY | Escape-последовательности `\033[3Xm` и `\033[4Xm` для стилизации вывода терминала |

## Структура проекта и реализованные модули

Вся кодовая база проекта структурирована по директориям `src/01`–`src/05`. Каждый скрипт автономен, наделен минимальными зависимостями и строго определенной сферой ответственности.

| Файл / Модуль | Назначение и функционал | Применяемые концепции / Системные вызовы |
| :--- | :--- | :--- |
| [./src/01/main.sh](./src/01/main.sh) | Точка входа модуля 01. Принимает текстовый параметр и выводит его в stdout | Смена рабочего каталога `cd "$(dirname "$0")"`, подключение валидации через `source` |
| [./src/01/validate.sh](./src/01/validate.sh) | Валидатор модуля 01. Проверяет количество переданных параметров и тип данных | Контроль `$# -ne 1`, регулярное выражение `^-?[0-9]+(\.[0-9]+)?$` для отсечения чисел |
| [./src/02/main.sh](./src/02/main.sh) | Точка входа модуля 02. Сбор телеметрии, вывод на экран и опциональное сохранение в лог | Command substitution `$()`, интерактивный ввод `read -p`, генерация имени `date +"%d_%m_%y_%H_%M_%S".status` |
| [./src/02/validate.sh](./src/02/validate.sh) | Валидатор модуля 02. Запрещает передачу любых параметров командной строки | Контроль `$# -ne 0`, вывод сообщения об ошибке и аварийное завершение `exit 1` |
| [./src/02/HOSTNAME.sh](./src/02/HOSTNAME.sh) | Извлечение сетевого имени хоста | Вызов системной утилиты `hostname` |
| [./src/02/TIMEZONE.sh](./src/02/TIMEZONE.sh) | Определение временной зоны хоста и смещения UTC | Вызовы `timedatectl show --property=Timezone --value` и `date +"UTC %:::z"` |
| [./src/02/USER.sh](./src/02/USER.sh) | Определение текущего пользователя, запустившего скрипт | Вызов системной команды `whoami` |
| [./src/02/OS.sh](./src/02/OS.sh) | Получение человекочитаемого наименования операционной системы | Парсинг системного файла `source /etc/os-release`, чтение переменной `${PRETTY_NAME}` |
| [./src/02/DATE.sh](./src/02/DATE.sh) | Получение текущей даты и системного времени хоста | Форматированный вызов `date +"%d %B %Y %H:%M:%S"` |
| [./src/02/UPTIME.sh](./src/02/UPTIME.sh) | Получение длительности работы операционной системы | Вызов команды `uptime -p` (human-readable uptime) |
| [./src/02/UPTIME_SEC.sh](./src/02/UPTIME_SEC.sh) | Получение точного аптайма системы в секундах | Чтение первого поля файла виртуальной файловой системы ядра `awk '{print $1}' /proc/uptime` |
| [./src/02/IP.sh](./src/02/IP.sh) | Определение первичного IPv4-адреса хоста | Вызов `hostname -I` с последующей фильтрацией первого адреса через `awk '{print $1}'` |
| [./src/02/MASK.sh](./src/02/MASK.sh) | Расчет сетевой маски интерфейса маршрута по умолчанию в формате IPv4 | Парсинг `ip route`, `ip addr`, побитовый сдвиг `0xFFFFFFFF << (32 - cidr)`, расчет байт маски |
| [./src/02/GATEWAY.sh](./src/02/GATEWAY.sh) | Определение IP-адреса шлюза по умолчанию | Парсинг таблицы маршрутизации `ip route show default \| awk '{print $3}'` |
| [./src/02/RAM_TOTAL.sh](./src/02/RAM_TOTAL.sh) | Расчет общего объема физической оперативной памяти хоста в ГБ | Потоковый разбор `free \| grep Mem`, деление на `1024^2` в `awk '{printf "%.3f GB", $2/1024/1024}'` |
| [./src/02/RAM_USED.sh](./src/02/RAM_USED.sh) | Расчет используемого объема оперативной памяти хоста в ГБ | Разбор вывода `free \| grep Mem`, вычисление `awk '{printf "%.3f GB", $3/1024/1024}'` |
| [./src/02/RAM_FREE.sh](./src/02/RAM_FREE.sh) | Расчет свободного объема оперативной памяти хоста в ГБ | Разбор вывода `free \| grep Mem`, вычисление `awk '{printf "%.3f GB", $4/1024/1024}'` |
| [./src/02/SPACE_ROOT.sh](./src/02/SPACE_ROOT.sh) | Расчет общего дискового пространства корневого раздела `/` в МБ | Анализ дисковой статистики `df /`, обработка второй строки `awk 'NR==2 {printf "%.2f MB", $2/1024}'` |
| [./src/02/SPACE_ROOT_USED.sh](./src/02/SPACE_ROOT_USED.sh) | Расчет занятого пространства корневого раздела `/` в МБ | Статистика `df /`, парсинг поля использованного пространства `awk 'NR==2 {printf "%.2f MB", $3/1024}'` |
| [./src/02/SPACE_ROOT_FREE.sh](./src/02/SPACE_ROOT_FREE.sh) | Расчет свободного пространства корневого раздела `/` в МБ | Статистика `df /`, парсинг поля доступного пространства `awk 'NR==2 {printf "%.2f MB", $4/1024}'` |
| [./src/03/main.sh](./src/03/main.sh) | Точка входа модуля 03. CLI-запуск с ручной передачей 4 цветов оформления | Оркестрация модулей `validate.sh`, `colors.sh`, `print_info.sh` с передачей параметров палитры |
| [./src/03/validate.sh](./src/03/validate.sh) | Валидатор модуля 03. Проверка параметров палитры и контрастности | Проверка `$# -ne 4`, regex `^[1-6]$`, проверка равенства `[ "$col1_bg" = "$col1_fg" ]` |
| [./src/03/colors.sh](./src/03/colors.sh) | Библиотека ANSI-цветов. Определение кодов текста, фона и функций | ANSI-коды `\033[3Xm`, `\033[4Xm`, `\033[0m`, функции сопоставления `bg_code()`, `fg_code()` |
| [./src/03/print_info.sh](./src/03/print_info.sh) | Модуль рендеринга таблицы системных параметров с заданной палитрой | Функция `print_info()`, форматирование строк с применением цветовых последовательностей |
| [./src/04/main.sh](./src/04/main.sh) | Точка входа модуля 04. Стилизованный мониторинг на основе конфигурации | Подключение `config.sh`, вывод таблицы метрик и текстовой расшифровки примененной цветовой схемы |

| [./src/04/colors.sh](./src/04/colors.sh) | Расширенная библиотека цветов с функцией вербального именования | Функции генерации ANSI-последовательностей и строкового представления названий `color_name()` |

5. Вывод ТОП-10 самых крупных исполняемых файлов (путь, размер, MD5-хеш).
